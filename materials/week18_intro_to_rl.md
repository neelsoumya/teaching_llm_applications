# Week 18 — Introduction to Reinforcement Learning

## Lecture Overview

Reinforcement learning (RL) underpins RLHF, DPO's theoretical grounding, GRPO, agentic decision-making, and the broader project of building systems that learn from interaction rather than from a fixed labelled dataset. This week we step back from LLMs specifically and build the classical RL foundations from first principles: Markov decision processes, value functions, the Bellman equation, dynamic programming, Monte Carlo and temporal-difference methods, Q-learning, and policy gradient methods — culminating in REINFORCE and a recap of how PPO (Week 13) builds on top of these ideas. This chapter is intended to be read before Week 13 if students have not previously studied RL, and works as a refresher otherwise.

---

## 1. What Is Reinforcement Learning?

Reinforcement learning is the study of how an **agent** should act in an **environment** to maximise cumulative **reward**, learning from the consequences of its own actions rather than from labelled examples.

This is fundamentally different from supervised learning:

| | Supervised Learning | Reinforcement Learning |
|---|---|---|
| Data | Fixed (x, y) pairs | Generated by agent's own actions |
| Feedback | Immediate, dense (label per example) | Delayed, sparse (reward may arrive much later) |
| Objective | Minimise prediction error | Maximise cumulative future reward |
| i.i.d. assumption | Yes | No — data distribution depends on the policy |
| Credit assignment | Not needed | Central problem (which past action caused this reward?) |

### 1.1 The Agent-Environment Loop

```
        ┌─────────────┐
   a_t  │             │  s_t, r_t
  ──────▶   Agent      │◀──────────
        │             │
        └─────────────┘
              │  a_t
              ▼
        ┌─────────────┐
        │ Environment │
        └─────────────┘
              │  s_{t+1}, r_{t+1}
              ▼
            (repeat)
```

At each timestep t:
1. The agent observes state s_t.
2. The agent selects action a_t according to its **policy** π.
3. The environment transitions to state s_{t+1} and emits reward r_{t+1}.
4. The cycle repeats.

### 1.2 Why RL Matters for LLMs

- RLHF (Week 13): the LLM is the policy; the "environment" is a single-step bandit problem (generate a response, receive a reward, episode ends).
- GRPO / RLOO (Week 13): group-relative variants of policy gradient methods for reasoning tasks.
- Agents (Week 10): the LLM acts in a genuinely multi-step environment with tools, observations, and delayed rewards.
- DPO (Week 16): derived from the optimal solution to an RL problem with a KL constraint, even though DPO training itself involves no explicit RL loop.

Understanding classical RL is what allows you to read papers, understand *why* PPO is shaped the way it is, and recognise when a problem genuinely needs RL versus when supervised or preference-based methods suffice.

## 2. Markov Decision Processes (MDPs)

An **MDP** formalises the RL problem as a tuple:

```
MDP = (S, A, P, R, γ)
```

- **S**: set of states
- **A**: set of actions
- **P(s'|s,a)**: transition probability — probability of reaching state s' given state s and action a
- **R(s,a,s')**: reward function
- **γ ∈ [0,1)**: discount factor

### 2.1 The Markov Property

```
P(s_{t+1} | s_t, a_t, s_{t-1}, a_{t-1}, ..., s_0, a_0) = P(s_{t+1} | s_t, a_t)
```

The future depends only on the present state and action, not on the full history. This is a modelling assumption — the state must be designed to contain all relevant information.

### 2.2 Policies

A **policy** π defines the agent's behaviour:

```
Deterministic policy:   a = π(s)
Stochastic policy:      π(a|s) = P(action = a | state = s)
```

LLM policies are stochastic: π_θ(y|x) is the probability the model assigns to completion y given prompt x.

### 2.3 Returns

The **return** is the cumulative discounted reward from time t:

```
G_t = r_{t+1} + γ r_{t+2} + γ² r_{t+3} + ...  = Σ_{k=0}^{∞} γ^k r_{t+k+1}
```

The discount factor γ controls how much the agent values future rewards relative to immediate ones:
- γ → 0: myopic agent, only cares about immediate reward.
- γ → 1: far-sighted agent, values future rewards almost as much as immediate ones.
- γ < 1 is also needed mathematically to ensure the sum converges for infinite-horizon problems.

For LLM RLHF, the "episode" is typically a single response generation (γ = 1, finite horizon of one action — though token-level formulations exist where γ < 1 across tokens).

## 3. Value Functions

### 3.1 State-Value Function

The expected return starting from state s, following policy π thereafter:

```
V^π(s) = E_π [ G_t | S_t = s ]  =  E_π [ Σ_{k=0}^{∞} γ^k r_{t+k+1} | S_t = s ]
```

### 3.2 Action-Value Function (Q-function)

The expected return starting from state s, taking action a, then following π:

```
Q^π(s,a) = E_π [ G_t | S_t = s, A_t = a ]
```

### 3.3 Relationship Between V and Q

```
V^π(s) = Σ_a π(a|s) Q^π(s,a)
```

### 3.4 The Advantage Function

```
A^π(s,a) = Q^π(s,a) − V^π(s)
```

The advantage measures how much better action a is than the average action in state s, under policy π. This is the quantity PPO (Week 13) directly optimises — and the same advantage concept appears in GRPO's group-relative normalisation.

---

## 4. The Bellman Equations

Value functions satisfy a recursive relationship — the cornerstone of RL theory.

### 4.1 Bellman Expectation Equation

```
V^π(s) = Σ_a π(a|s) Σ_{s'} P(s'|s,a) [R(s,a,s') + γ V^π(s')]
```

In words: the value of a state equals the expected immediate reward plus the discounted value of the next state, averaged over the policy's action choices and the environment's transition dynamics.

```
Q^π(s,a) = Σ_{s'} P(s'|s,a) [R(s,a,s') + γ Σ_{a'} π(a'|s') Q^π(s',a')]
```

### 4.2 Bellman Optimality Equation

The **optimal value function** V*(s) = max_π V^π(s) satisfies:

```
V*(s) = max_a Σ_{s'} P(s'|s,a) [R(s,a,s') + γ V*(s')]

Q*(s,a) = Σ_{s'} P(s'|s,a) [R(s,a,s') + γ max_{a'} Q*(s',a')]
```

The optimal policy simply selects the action with the highest Q*:

```
π*(s) = argmax_a Q*(s,a)
```

This recursive structure is what allows dynamic programming, and later, function approximation (deep RL), to compute or estimate value functions efficiently rather than enumerating every possible trajectory.

## 5. Dynamic Programming (When the Model Is Known)

If P and R are fully known, we can compute V* and Q* exactly using dynamic programming.

### 5.1 Value Iteration

Repeatedly apply the Bellman optimality update until convergence:

```
V_{k+1}(s) ← max_a Σ_{s'} P(s'|s,a)[R(s,a,s') + γ V_k(s')]    for all s
```

```python
def value_iteration(P, R, gamma=0.99, theta=1e-6):
    V = {s: 0.0 for s in states}
    while True:
        delta = 0
        for s in states:
            v_old = V[s]
            V[s] = max(
                sum(P[s][a][s_next] * (R[s][a][s_next] + gamma * V[s_next])
                    for s_next in states)
                for a in actions(s)
            )
            delta = max(delta, abs(v_old - V[s]))
        if delta < theta:
            break
    return V
```

### 5.2 Policy Iteration

Alternate between:
1. **Policy evaluation**: compute V^π for the current policy (solve the Bellman expectation equation).
2. **Policy improvement**: update π greedily with respect to V^π.

```
π_{k+1}(s) ← argmax_a Σ_{s'} P(s'|s,a)[R(s,a,s') + γ V^{π_k}(s')]
```

Both value iteration and policy iteration are guaranteed to converge to the optimal policy for finite MDPs, but require complete knowledge of P and R — rarely available in practice. This motivates model-free methods.

## 6. Model-Free Learning: Monte Carlo and TD

When the transition dynamics P are unknown (the usual case), the agent must learn from sampled experience.

### 6.1 Monte Carlo (MC) Methods

Run a full episode, then update value estimates using the *observed* return:

```
V(s_t) ← V(s_t) + α [G_t − V(s_t)]
```

where α is a learning rate and G_t is the actual observed cumulative discounted reward from that episode.

Properties:
- Unbiased estimate of V^π(s).
- High variance (depends on the entire random trajectory).
- Requires episodes to terminate before any update can be made.

### 6.2 Temporal-Difference (TD) Learning

Update value estimates after every single step, using a **bootstrapped** estimate of the return rather than waiting for the full episode:

```
V(s_t) ← V(s_t) + α [r_{t+1} + γ V(s_{t+1}) − V(s_t)]
                    └──────────── TD target ────────────┘
                    └──────────────── TD error δ_t ──────────────────┘
```

This is **TD(0)**: it uses one real reward plus a bootstrapped estimate of everything after that.

| | Monte Carlo | TD(0) |
|---|---|---|
| Bias | Unbiased | Biased (bootstraps from current estimate) |
| Variance | High | Lower |
| Updates | End of episode only | Every step |
| Works for non-terminating tasks | No | Yes |

TD methods are the workhorse of most practical RL algorithms because of their lower variance and ability to learn online.

### 6.3 The TD Error as a Learning Signal

The TD error δ_t = r_{t+1} + γV(s_{t+1}) − V(s_t) appears throughout RL: it is the basis of actor-critic methods (including PPO's advantage estimation via GAE, covered in Week 13) and has a documented correspondence to dopamine signalling in biological reward learning (Schultz et al., 1997) — one of the most striking convergences between machine learning theory and neuroscience.

## 7. Q-Learning and SARSA

### 7.1 Q-Learning (Off-Policy)

Learn Q* directly, regardless of the policy used to generate experience:

```
Q(s_t, a_t) ← Q(s_t, a_t) + α [r_{t+1} + γ max_{a'} Q(s_{t+1}, a') − Q(s_t, a_t)]
```

The `max_{a'}` makes this **off-policy**: it learns about the greedy policy even while the agent behaves differently (e.g. with ε-greedy exploration).

### 7.2 SARSA (On-Policy)

```
Q(s_t, a_t) ← Q(s_t, a_t) + α [r_{t+1} + γ Q(s_{t+1}, a_{t+1}) − Q(s_t, a_t)]
```

Uses the *actual* next action a_{t+1} taken by the current policy, rather than the max. This makes SARSA **on-policy**: it evaluates and improves the policy that is actually being followed, including its exploration behaviour.

### 7.3 Exploration vs Exploitation

The agent must balance:
- **Exploitation**: choosing the action currently believed to be best.
- **Exploration**: trying other actions to discover if they might be better.

**ε-greedy**: with probability ε choose a random action; otherwise choose argmax_a Q(s,a).

```python
def epsilon_greedy(Q, state, actions, epsilon=0.1):
    if random.random() < epsilon:
        return random.choice(actions)
    return max(actions, key=lambda a: Q[state, a])
```

This exploration-exploitation trade-off reappears in LLM RL: temperature sampling during PPO rollouts, entropy bonuses, and the choice of how many completions to sample per prompt in GRPO all serve an analogous exploration purpose.

### 7.4 Deep Q-Networks (DQN)

Mnih et al. (2015): when the state space is too large to tabulate (e.g. raw pixels), approximate Q(s,a) with a neural network Q_θ(s,a). Key innovations that made this stable:
- **Experience replay**: store transitions in a buffer and sample mini-batches, breaking temporal correlation.
- **Target network**: use a slowly-updated copy of the network to compute TD targets, reducing instability from a constantly-shifting target.

DQN is value-based: it learns Q and derives the policy implicitly. This works well for discrete action spaces (e.g. Atari) but does not scale naturally to the enormous, structured action spaces of language generation (every possible next token, every possible full response) — which motivates policy-based methods.

## 8. Policy Gradient Methods

Rather than learning a value function and deriving a policy from it, **policy gradient methods** directly parameterise and optimise the policy π_θ.

### 8.1 The Policy Gradient Theorem

We want to maximise the expected return:

```
J(θ) = E_{τ ~ π_θ} [ Σ_t γ^t r_t ]
```

The policy gradient theorem (Sutton et al., 2000) gives:

```
∇_θ J(θ) = E_{π_θ} [ Σ_t ∇_θ log π_θ(a_t|s_t) · G_t ]
```

This remarkable result says: we can estimate the gradient of expected return *without knowing the environment dynamics at all* — we only need to be able to sample trajectories and observe their returns. The proof uses the **log-derivative trick**:

```
∇_θ π_θ(a|s) = π_θ(a|s) · ∇_θ log π_θ(a|s)
```

which lets us rewrite an expectation over the policy as something we can estimate by sampling.

### 8.2 REINFORCE

The simplest policy gradient algorithm (Williams, 1992):

```
θ ← θ + α · Σ_t ∇_θ log π_θ(a_t|s_t) · G_t
```

```python
def reinforce_update(policy, trajectory, optimiser, gamma=0.99):
    states, actions, rewards = trajectory
    returns = []
    G = 0
    for r in reversed(rewards):
        G = r + gamma * G
        returns.insert(0, G)
    returns = torch.tensor(returns)
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)  # normalise

    loss = 0
    for s, a, G_t in zip(states, actions, returns):
        log_prob = policy.log_prob(a, s)
        loss += -log_prob * G_t

    optimiser.zero_grad()
    loss.backward()
    optimiser.step()
```

**Intuition**: increase the probability of actions that led to high return; decrease the probability of actions that led to low return. The magnitude of the update scales with how good or bad the outcome was.

### 8.3 The Variance Problem and Baselines

REINFORCE has very high variance because G_t depends on the entire random future trajectory. A **baseline** b(s) reduces variance without introducing bias:

```
∇_θ J(θ) = E [ Σ_t ∇_θ log π_θ(a_t|s_t) · (G_t − b(s_t)) ]
```

Subtracting any function of state alone (not of action) leaves the gradient estimator unbiased — because `E_a[∇_θ log π_θ(a|s)] = 0` for any state-only baseline — but reduces variance substantially when b(s) ≈ V(s).

### 8.4 Actor-Critic Methods

Use a learned value function V_φ(s) as the baseline, and replace G_t with the TD error or advantage estimate:

```
Actor update:   θ ← θ + α_θ · ∇_θ log π_θ(a_t|s_t) · A(s_t, a_t)
Critic update:  φ ← φ + α_φ · ∇_φ (G_t − V_φ(s_t))²
```

This is exactly the actor-critic structure used in PPO (Week 13): the LLM is the actor, a separate value head is the critic, and the advantage A(s_t, a_t) is estimated via GAE rather than the raw return.

### 8.5 From REINFORCE to PPO: The Throughline

| Algorithm | Baseline | On/off-policy updates | Notes |
|-----------|----------|----------------------|-------|
| REINFORCE | None | Single update per trajectory | High variance |
| REINFORCE + baseline | V(s) | Single update per trajectory | Lower variance |
| Actor-Critic | Learned V_φ | Single update per trajectory | TD-based advantage |
| TRPO (Schulman et al., 2015) | Learned V_φ | Constrained trust-region update | Theoretically grounded step-size control |
| PPO (Schulman et al., 2017) | Learned V_φ | Clipped surrogate, multiple epochs per batch | TRPO's benefits with much simpler implementation |
| GRPO (DeepSeek, 2024) | Group-relative mean reward | Multiple updates per batch | No critic network needed |

PPO can be understood as: *take the policy gradient theorem, add a learned baseline (critic) to reduce variance, and add a clipping mechanism to prevent any single update from moving the policy too far (approximating TRPO's trust region constraint without the heavy machinery)*. This is exactly the algorithm introduced in Week 13's RLHF deep dive — now you have the foundations to see precisely where each piece comes from.

## 9. Exploration in Large Action Spaces

Language model "actions" are draws from a vocabulary of tens of thousands of tokens, and a full "trajectory" is a complete response — an enormous combinatorial action space compared to classic RL benchmarks (e.g. 4 actions in a gridworld, 18 actions in Atari).

This has practical consequences:
- Naive ε-greedy exploration over tokens is nonsensical; instead, exploration happens through **sampling temperature** in the policy's own probability distribution.
- The reward signal in RLHF is typically only available at the *end* of a full response (sparse, episodic reward) — closer to a single-step bandit than to a long-horizon control problem.
- For multi-step agentic tasks (Week 10) the action space and horizon are both large, making credit assignment genuinely difficult — this is an active research area connecting classical RL credit-assignment theory to LLM agents.

## 10. Multi-Armed Bandits: The Simplest RL Problem

A useful simplification: the **multi-armed bandit** has no state transitions at all — just a single state, k actions ("arms"), and a reward distribution per arm.

```
At each step: choose arm a, observe reward r ~ R(a), repeat.
Goal: maximise cumulative reward / minimise regret.
```

RLHF for a single-turn LLM response is structurally a **contextual bandit**: the state (context) is the prompt x, the action is the full response y, and the episode ends after one action. This is why RLHF can be implemented without the full machinery of multi-step value functions — though current implementations still use a critic for variance reduction via GAE.

### 10.1 Regret

```
Regret(T) = Σ_{t=1}^{T} (r* − r_t)
```

where r* is the expected reward of the best arm. Good bandit algorithms achieve sub-linear (e.g. logarithmic) regret in T.

### 10.2 Upper Confidence Bound (UCB)

```
a_t = argmax_a [ Q̄(a) + c · √(ln(t) / N(a)) ]
```

Balances exploitation (high estimated value Q̄(a)) with exploration (bonus for actions tried less often, N(a) small). This "optimism under uncertainty" principle reappears conceptually in exploration bonuses used in some RLHF and agent research.
